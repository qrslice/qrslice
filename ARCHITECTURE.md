# QRslice — System Architecture

**Version 1.0 — 2026-10-09**
**Status: DRAFT — describes the pivoted QRslice (QR layer, no POS/KDS)**

> QRslice is the restaurant's QR layer: tap cards, feedback, reviews, and digital
> menus. Hardware-led acquisition, software-retained revenue. It is NOT a POS.

---

## 1. Stack

| Layer | Choice |
|-------|--------|
| Framework | Next.js 16 (App Router), React 19, TypeScript |
| Styling | Tailwind CSS v4 |
| Authentication | Clerk (`@clerk/nextjs`) |
| Database / Storage | Supabase (Postgres, Storage, RLS) |
| Payments | Razorpay — **hardware storefront orders & owner subscriptions**. Guests dining in restaurants never pay through QRslice. Fail-closed: missing keys throw 503 error, server HMAC-SHA256 signature verification. |
| QR generation | Server-side library (`qrcode`, no external QR APIs) |
| Hosting | Cloudflare Workers via OpenNext (`@opennextjs/cloudflare`) + Supabase (data) |

No new dependencies without explicit human approval.

## 2. System components

```
┌─────────────────┐     ┌─────────────────────┐     ┌──────────────────┐
│  PHYSICAL       │     │  PUBLIC HARDWARE    │     │  OWNER PORTAL    │
│  NFC/QR card    │────▶│  STOREFRONT         │────▶│  /dashboard      │
│  & standees     │ tap │  /products, /cart   │claim │  feedback inbox  │
└─────────────────┘     │  /checkout (Razorpay)│     │  cards, menu     │
                        │  /track-order       │     └──────────────────┘
                        │  /activate (static) │     ┌──────────────────┐
                        │  /a/{card_id}       │     │  SUPERADMIN      │
                        │  /m/{slug} menu     │     │  /super/orders   │
                        │  /tools/* (free QR) │     │  /super/cards    │
                        └─────────────────────┘     │  /super/finance  │
                                                    └──────────────────┘
```

### 2.1 Physical hardware products
- CR80 PVC (85.6 × 54 mm), NTAG213 contactless smart microchip.
- Architectural acrylic standees, matte black metal cards, and counter displays.
- NFC chip and printed QR both encode `https://qrslice.com/a/{card_id}`.
- Human-typeable Card ID printed under the QR (e.g. `QS-8F3K2`).
- Artwork generated by `src/lib/card-artwork.ts` (single code path for preview and print export).

### 2.2 Public web & hardware storefront
- `/` — Homepage featuring hardware showcase, benefits strip, and progressive GSAP animations with safety timeouts and `prefers-reduced-motion` compliance.
- `/products` & `/products/[slug]` — Catalog displaying real reviews only (zero stars until verified reviews exist).
- `/cart` & `/checkout` — Cart drawer and checkout page backed by Razorpay. Fails closed with clear error if payment gateway keys are unconfigured. Single authoritative checkout route (no free-order leaks).
- `/checkout/success` — Live fulfillment status and downloadable GST-compliant receipt for unregistered business entity (0% GST, no ITC).
- `/track-order` — Order status portal displaying manufacturing milestones and courier tracking.
- `GET /a/{card_id}` — Resolves a card ID server-side, rate-limited (30 req / 60 s / IP).
- `/activate` — Fully static (`○ /activate`) claim flow. Reads parameters client-side in `useEffect` to prevent worker CPU spikes under load.
- `/m/{slug}` — Public view-only digital menu. No ordering, no cart, no guest payments.
- `/tools/*` — Free client-side QR generation tools (Google Review, UPI, vCard, Social, WiFi, URL).
- `/robots.txt` & `/sitemap.xml` — Public static assets allowlisted in proxy middleware.

### 2.3 Owner portal (`/dashboard`, auth required via Clerk)
- **Feedback inbox** — Guest ratings and comments land here; instant alerts for ≤3 stars.
- **My cards** — Rename, re-point destination (menu vs Google review) with instant effect, disable lost cards.
- **Menu editor** — Simple item/price editor feeding public view-only `/m/{slug}`.
- **Reputation settings** — Outlet's Google review link (validated URL format), review routing copy.

### 2.4 Superadmin (`/super`, server-enforced superadmin role)
- `/super/orders` — Storefront hardware orders, packing slips, invoices, and fulfillment stages.
- `/super/cards` & `/super/batches` — Card designer, live SVG preview, batch generation, print export ZIP.
- `/super/finance` — Razorpay settlement reconciliation and hardware order revenue tracking.
- `/super/customers` — Customer directory, order history, and lifetime value.

### 2.5 Payments & Billing
- Hardware Storefront: Razorpay orders verified server-side with HMAC-SHA256 (`RAZORPAY_KEY_SECRET`). Zero test-signature bypasses.
- Restaurant Owners: Subscriptions handled via Razorpay (one-time hardware purchases carry zero recurring fees).
- Guests dining in restaurants pay nothing through QRslice, ever.
- Entity Status: Unregistered small business under GST law (0% GST charged, no Input Tax Credit).

## 3. Data model (new tables)

```sql
-- Card production batches
card_batches (
  id uuid PK,
  name text,
  theme text,                       -- 'premium-plum' | 'google-review' | 'minimal-mono'
  design_json jsonb,                 -- logo path, business name, colors, copy
  quantity int,
  status text,                      -- draft → exported → manufactured
  created_at timestamptz,
  created_by uuid
);

-- Individual physical cards
cards (
  id uuid PK,
  batch_id uuid FK → card_batches,
  card_id text UNIQUE,              -- public ID, e.g. QS-8F3K2 (Crockford base32, no 0/O/1/I/L)
  claim_token_hash text,            -- hashed secret; raw token shown ONCE at creation
  activation_url text,              -- https://qrslice.com/a/{card_id}
  status text,                      -- manufactured → in_stock → assigned → claimed → active (+ disabled)
  tenant_id uuid NULL FK,           -- null until claimed
  purpose text,                     -- menu | reputation | profile
  svg_front text, svg_back text,    -- artwork frozen at export
  created_at timestamptz, claimed_at timestamptz NULL
);

-- Guest feedback (private; feeds the owner inbox)
feedback (
  id uuid PK,
  tenant_id uuid FK,
  card_id text NULL FK,             -- which card, if any
  rating int CHECK (1..5),
  comment text,
  created_at timestamptz
);

-- Public menus (one per tenant, view-only)
menus (
  tenant_id uuid PK FK,
  slug text UNIQUE,
  items jsonb,                      -- [{name, price_paise, desc, veg}]
  updated_at timestamptz
);

-- Storefront hardware orders (source of truth in Supabase)
shop_orders (
  id uuid PK DEFAULT gen_random_uuid(),
  order_number text UNIQUE,         -- ORD-YYYY-XXXXXX
  customer_name text,
  customer_email text,
  customer_phone text,
  shipping_address jsonb,
  gstin text NULL,                  -- optional buyer GSTIN
  business_legal_name text NULL,
  subtotal_paise bigint,
  discount_paise bigint,
  shipping_paise bigint,
  tax_paise bigint DEFAULT 0,       -- 0 paise (unregistered entity)
  total_paise bigint,
  status text,                      -- pending → paid → processing → shipped → delivered
  razorpay_order_id text,
  razorpay_payment_id text,
  tracking_number text,
  courier_partner text,
  created_at timestamptz DEFAULT now()
);

-- Storefront hardware order items
shop_order_items (
  id uuid PK DEFAULT gen_random_uuid(),
  order_id uuid FK → shop_orders(id),
  product_id text,
  title text,
  slug text,
  finish text,
  custom_business_name text,
  custom_destination_url text,
  unit_price_paise bigint,
  quantity int,
  total_paise bigint
);
```

Existing tables reused: tenants/restaurants, subscriptions (owner plans),
users/roles. **RLS on every new table**: super-admin full access; owners see
only their own tenant's rows; public reads only via the rate-limited resolve
path, never direct table access.

## 4. Key flows

### 4.1 Provision → claim (factory to counter)
1. Superadmin designs batch → generates N cards (`manufactured`).
2. Export ZIP → printer produces physical cards.
3. Cards ship; on dispatch → `assigned` (linked to order/buyer if known).
4. Owner taps/scans → `/a/{card_id}` → `/activate` → signs in → claims once →
   picks destination → `active`. Raw claim token verified **only at this moment**.

### 4.2 Guest tap → feedback
1. Tap NFC or scan QR → `/a/{card_id}` (server resolves, rate-limited).
2. Guest sees feedback page: star rating + comment (feedback-first).
3. Google review link **always visible** to every guest — never gated behind a
   high rating (Google policy compliance is a product requirement, not a nicety).
4. Feedback lands in the owner's inbox; ≤3 stars triggers the low-rating alert.

### 4.3 Hardware Storefront Purchase
1. Buyer configures products on `/products/[slug]`, customizes branding, and adds to cart.
2. Checkout on `/checkout` calls `/api/shop/checkout` which creates order in Supabase and Razorpay order.
3. Buyer pays via real Razorpay modal.
4. Server verifies HMAC-SHA256 signature in `/api/shop/checkout/verify` with `RAZORPAY_KEY_SECRET`.
5. Order marked paid in Supabase; buyer redirected to `/checkout/success` with instant GST receipt.

### 4.4 Trial → paid (Restaurant Owner SaaS)
1. Card purchase starts a 3-month Pro trial clock on the tenant.
2. Owner sees trial countdown in `/dashboard/billing`.
3. Razorpay subscription (monthly or annual) before expiry, or back to free tier
   (1 card, menu only, no inbox).

## 5. Explicitly out of scope

POS billing, KDS, inventory, settlements, Z-reports, split bills, staff
management, purchase orders, suppliers, guest online payment for dining, table management,
offline POS. **If a feature moves money inside a restaurant, it does not belong
in this product.** The old POS/KDS code is parked on a branch, not deleted.

Also out: WhatsApp (removed permanently), fabricated metrics/testimonials on
any surface, sample/placeholder data persisted as real (no sample GSTIN-style
defaults anywhere).

## 6. Non-functional requirements

- **Tap reliability:** NFC must trigger on iPhone (screen on) and Android
  (screen locked) at first tap. Every batch spot-checked with TagInfo + 2 phones.
- **QR scannability:** EC-H, quiet zone, vector source; verified on a budget
  Android in real restaurant light before any batch ships.
- **Performance:** public pages < 500 KB transfer, LCP < 2 s on 4G.
- **Reduced motion respected** on all marketing/public surfaces via CSS and GSAP bypasses.
- **Print fidelity:** preview SVG and export SVG are byte-identical (one
  generator, hash-compared in tests).
